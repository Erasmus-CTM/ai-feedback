# Shared layout lifecycle candidate

`ui/ctm-layout.js` is the canonical shared CTM implementation. This integration draft registers it through `ctm.layout.use()` before reveal/store/progress and Python editor consumers. Release remains gated by complete canonical browser/store/course evidence.

`CTMLayout.ready(callback)` releases shared reveal/save/progress initialization once complete build-time content has been parsed. `ctm.ui.finalize()` first finalizes the saved-answer manifest, then seals the actual document tail with a non-rendering `ctm-layout-ready` marker. The umbrella end filter runs this after every component, including on reveal-only pages. Standalone component re-finalization replaces the old marker after the new tail. A plain standalone library filter without an end finalizer retains DOMContentLoaded fallback. The bounded parser observer handles both newly inserted nodes and streamed text appended to existing nodes, then disconnects. Scripts loaded after parsing retain their previous synchronous initialization. It does not delay startup by a timer, start Python or execute answers. This lifecycle does not guarantee an order relative to every deferred third-party module.

`CTMLayout.fitEditor(editor, container, {minHeight})` consumes supported Monaco APIs with `automaticLayout: false`. Bind it during editor construction, outside ResizeObserver delivery: it preserves the components' initial synchronous fit. It owns the native container ResizeObserver and content-size subscription. Later callbacks copy the latest content-box dimensions and schedule one rendering-frame task; that task writes the existing fit-to-content height and calls `editor.layout`. Fractional/untransformed box dimensions and Monaco's minimum hidden dimensions are retained. A height write receives its new box through native observation. Editor disposal cancels pending work, disconnects the scoped observer and disposes subscriptions. A window-resize fallback exists where ResizeObserver is absent.

`CTMLayout.task(callback)` is the small one-pending-frame scheduler used by that integration. Repeated notifications while rendering is paused retain one task. No idle polling or time-based fallback is added.

This is local integration work. Quarto and Monaco sources, native constructors and raw errors remain unchanged. The shared early-startup hypothesis and later editor feedback path need separate causal/behavior evidence; a green helper unit test alone does not clear strict store/course acceptance or fake-clock behavior. Consumers must register this exact canonical dependency rather than copy the helper.
